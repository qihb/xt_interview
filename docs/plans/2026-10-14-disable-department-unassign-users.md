# 部门禁用与用户解绑 · 落地计划

**目标**：禁用部门时检查关联用户；有关联用户则提示“禁用后将把用户改为未分配”，用户确认后完成部门禁用和用户解绑，取消则保持不变；禁用部门不再出现在用户管理部门树和用户新建/编辑部门选择中。
**技术栈 / 约束**：Spring Boot 4.0.6、JPA、现有统一错误响应；Vue 3、TypeScript、Pinia、Element Plus；遵循按 feature 组织代码、Controller/Service 分层、事务处理和前后端分层测试约定。
**涉及文件**：
- 后端：`DepartmentService`、`DepartmentServiceImpl`、`DepartmentController`、`AccountRepository`、必要的 DTO/异常类，以及对应 Controller/Service 测试。
- 前端：部门 API 类型、部门列表 composable、`DepartmentTree.vue`、`DepartmentSelect.vue`、`UserDialog.vue`、`DepartmentManagement.vue`，以及部门树/选择器/管理页测试。
- 文档：本计划文档；如接口行为发生变化，同步更新 README API 说明。
**关键决策**：
- 禁用流程采用两次请求：第一次将部门状态改为 0 时，如果存在未删除用户，后端返回 HTTP 409，响应 `details` 携带关联用户数量和确认标识；前端弹出确认框，用户确认后携带明确的“解绑用户”标识重试。
- 确认后的“解绑用户 + 禁用部门”必须在同一个 Service 事务中完成；取消确认不发起第二次请求，部门和用户关联保持原状。
- 仅在“启用 -> 禁用”且存在关联用户时要求确认；无关联用户直接禁用，重新启用不需要确认。
- 禁用部门仍保留在部门管理列表中，便于编辑和重新启用；用户管理左侧部门树、用户新建/编辑表单的部门选择只展示 `status = 1` 的部门。
- 禁用后用户的 `department_id` 置为 `NULL`，用户列表显示“未分配”；不删除用户、不删除部门记录。
- 前端确认提示以接口返回的关联数量为准，禁止仅根据当前页面列表推断用户数量。
- 用户解绑禁止逐条加载实体后 `save`；同步流程使用带索引的批量 `UPDATE`，减少内存占用、网络往返和事务耗时。
- 预留异步任务模式：当关联用户数量超过可配置阈值时，确认后创建解绑任务并返回任务 ID，由后台分批执行、记录进度、支持重试；任务必须幂等，不能重复清理或误影响其他部门。
**执行约定**：本文件仅为计划；用户确认后再执行，并按指定阶段逐步交付。每完成一个阶段更新勾选状态和验证结果。
