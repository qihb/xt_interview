# 前端角色权限控制 · 落地计划

**目标**：根据当前登录用户的 `roleLevel` 控制用户管理和部门管理页面的查看、刷新、新增、编辑、删除操作，无权限操作不显示对应按钮。
**技术栈 / 约束**：Vue 3 Composition API、TypeScript、Pinia、Vue Router、Element Plus；遵循 `features/<feature>` 架构、feature 通过 `index.ts` 暴露公共 API、页面按业务域组织，以及现有 JWT 登录用户状态管理约定。
**涉及文件**：
- 认证状态：`frontend/web/src/features/auth/api/index.ts`、`frontend/web/src/features/auth/stores/user.ts`、`frontend/web/src/features/auth/index.ts`。
- 权限能力：新增 `frontend/web/src/features/auth/permissions.ts`（或同等 feature 内权限工具），集中定义角色级别、操作类型和判断函数。
- 页面接入：`frontend/web/src/views/account/UserManagement.vue`、`frontend/web/src/views/department/DepartmentManagement.vue`、必要时调整 `MainLayout.vue` 与 `router/index.ts`。
- 测试：认证 Store/权限工具测试、用户管理页测试、部门管理页测试、路由鉴权测试。
- 后端兜底评估：现有 `AccountController`、`DepartmentController` 目前需要确认是否已有角色校验；前端隐藏按钮不能替代接口级权限校验。
**权限矩阵**：

| `roleLevel` | 查看 | 刷新 | 新增 | 编辑 | 删除 |
| --- | --- | --- | --- | --- | --- |
| 1 用户权限 | 有 | 有 | 无 | 无 | 无 |
| 2 管理员权限 | 有 | 有 | 有 | 有 | 无 |
| 3 超级管理员 | 有 | 有 | 有 | 有 | 有 |

**关键决策**：
- 当前按登录响应中的 `user.roleLevel` 判断权限，Store 从持久化用户信息恢复后统一提供 `hasPermission` / `can` 能力，页面不直接散落比较数字。
- “查看”和“刷新”作为页面基础能力，不额外隐藏列表和刷新按钮；新增、编辑、删除无权限时隐藏。
- 采用“隐藏按钮 + 统一权限函数拦截”的双层前端实现，避免未来新增入口时只漏做模板控制。
- 路由继续要求登录；本次不新增角色级路由限制，两个管理页面对三种角色均可查看。
- 前端权限仅改善交互体验，不能作为安全边界；若后端尚未按角色限制写接口，计划中同步补充 Controller/Service 层 403 校验和接口测试。
**执行约定**：本文件仅为计划；用户确认后再执行，并按用户指定的阶段逐步交付。每完成一个阶段更新勾选状态和验证结果。
